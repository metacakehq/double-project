# The Double Project: an autonomous trading system, codified

The Double Project is Ken Ott's experiment in letting an AI run a small brokerage account by itself under locked rules. Campaign: turn $1,000 into $2,000 in a Robinhood cash account, started 2026-07-24. The operator is Claude, running as two claude.ai scheduled tasks (a weekday daily run that chains four checks through the trading day, and a Sunday scout). Ken sets the objective and approves rule changes; the system trades without per-trade approval.

This repo is the system, written down so it can be read, shared, audited and updated. It is not the live state. Live state (positions, balances, watchlist) lives in Dropbox and is marked sensitive there; this repo carries the rules, the architecture, the decision history, the operating lessons and an assessment.

GitHub: `metacakehq/double-project` (public since 2026-11-24, Ken: "make this public for now"). The git folder is in Dropbox, so commit from one Mac at a time and push after every commit.

## For other operators
The system is installable on another account: `INSTALL.md`. Every installed copy publishes its runs and trades to `data/<handle>/` and its Sunday scout prints learning proposals; the operator pushes both here with one command each (`CONTRIBUTING.md`). Running the system means committing its results to the community (Ken, 2026-11-24). Accepted learnings go into the rulebook tagged `[community]` and come back to every operator as the next skill-update prompt. The repo recommends rules; it never writes into anyone's account. This repo is public; anyone with the link can read it and fork it. Write access and merges stay with the maintainer.

## Sensitivity
- The brokerage account identifier is redacted everywhere in this repo as `<ACCOUNT>` and is the one thing that never appears, in any file, for any operator. It lives in the operator's own ROLE files and live skill. Both scripts refuse a record that contains one.
- Everything else the system did is community data, by Ken's decision of 2026-11-24: trade prices, P&L per trade, account values, run-by-run actions. They are in `data/` and `history/` and are published for every operator who runs the system. The repo is public.
- No credentials, tokens or order IDs are kept here.

## Rules of this repo
1. Dropbox is the record; this repo is the codification. Never edit a Dropbox state or status file from here.
2. Rule text changes happen in the live skill (Ken saves it) or in the state file (the run records them). This repo follows; it does not lead. The one exception is `rules/RULEBOOK.md`, which is allowed to be ahead of the skill when it merges state-carried rules into one document, and must say so.
3. Every sync appends to `CHANGELOG.md`.
4. Other operators' learnings arrive as files under `learnings/proposed/` and their data as rows under `data/<handle>/`, both by pull request, never carrying an account identifier. A learning changes a rule only after the maintainer accepts it (`CONTRIBUTING.md`).
